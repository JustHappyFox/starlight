## 1. Архитектурные решения (почему так)

- **2026-11-24 — Быстрая оплата «как на Fragment»** (`webapp/src/pages/Owner.tsx`): главная кнопка
  «Оплатить в Wallet» сразу открывает Wallet в Telegram через `tonConnectUI.openSingleWalletModal('telegram-wallet')`
  (без списка кошельков), `actionsConfiguration.returnStrategy='back'` + `twaReturnUrl = config.appLink` — после
  подтверждения пользователь возвращается в мини-апп. Первый раз: подключение + подтверждение; дальше — одно
  касание. Остальные кошельки — строка «Другой кошелёк» (обычный список), вручную — `ton://transfer` + комментарий.
  TON Connect подключает только некастодиальную часть Wallet; обычный (кастодиальный) баланс @wallet так не платит —
  только ручной перевод с комментарием (или мерчант-API Wallet Pay — не реализовано).
- **2026-11-24 — Шаблон Starlight удалён.** Репозиторий был стартером Netlify (Astro Starlight). Заменён на
  монорепо `server/` + `webapp/` + `shared/`. Бот не может жить на Netlify (нужен постоянный процесс, SQLite,
  планировщик) → основной деплой — Docker на VPS. `netlify.toml` собирает только статический фронт (опционально).
- **2026-11-24 — Кнопка под постом — `url`-кнопка `t.me/<bot>/<app>?startapp=<gid>`**, а не `web_app`:
  `web_app`-инлайн-кнопки работают только в личке с ботом, в каналах — нет.
- **2026-11-24 — Кнопка под постом одна для всех.** Текст инлайн-кнопки нельзя сделать разным для разных
  пользователей. Поэтому «Увеличить шанс» живёт внутри мини-аппа (нижняя кнопка Telegram MainButton после
  участия), а текст кнопки поста меняется глобально по фазам: `«<текст> (N)»` → `«⏳ Подводим итоги…»` → `«🏆 Результаты»`.
- **2026-11-24 — Ловушки только внутри мини-аппа.** В инлайн-клавиатуре Telegram невидимую кнопку сделать
  нельзя (любая кнопка видна). Поэтому: (1) DOM-кнопка «Участвовать» за пределами экрана (`.hp`),
  (2) скрытое поле `website` в форме, (3) эндпоинт-приманка `POST /api/g/:id/participate`, который настоящий
  клиент никогда не вызывает. Настоящая кнопка участия в Telegram — **нативная MainButton, её нет в DOM**,
  поэтому DOM-кликеры до неё не дотягиваются, а приманку находят.
- **2026-11-24 — Ловушка отвечает «успехом».** Бот не должен понять, что попался. Бан раскрывается только
  при нажатии настоящей кнопки (`403 banned` + попап «Доступ заблокирован»). `GET /api/g/:id` бан не показывает.
  3 срабатывания в разных розыгрышах → глобальный бан (`HONEYPOT_GLOBAL_BAN_HITS`). Снять: `/unban <id>`.
- **2026-11-24 — Защита участников:** призы оплачиваются заранее (эскроу у бота); после оплаты условия
  менять нельзя (`409 locked`); розыгрыш доказуемо честный (хеш seed публикуется в посте до старта, после —
  раскрывается; энтропия — хеш блока мастерчейна TON; скрипт `npm run verify -w server -- proof.json`);
  в протоколе — псевдонимы `sha256(gid:uid)[0..16]`, а не id пользователей; номер телефона не хранится, только страна.
- **2026-11-24 — Билеты:** 1 за участие + 1 за каждого приглашённого, который сам прошёл все проверки и не
  забанен; потолок `REF_TICKET_CAP`. Один человек — максимум один приз (выбор без возвращения).
- **2026-11-24 — Перед выдачей приза** победитель перепроверяется (подписка, глобальный бан); не прошёл —
  `disqualified` в протоколе, розыгрыш идёт дальше. Призов больше, чем участников → запись в `refunds` + уведомления.
- **2026-11-24 — Страна = страна номера телефона** (`requestContact` → libphonenumber). Telegram не отдаёт
  страну иначе. Номера Fragment `+888` страны не имеют → не проходят ограничение. IP-страна — только если
  сервер за Cloudflare (`CF-IPCountry`, `GEO_IP_MODE=log|enforce`), VPN её обходит.
- **2026-11-24 — Username обязателен для участия:** Fragment ищет получателя только по @username. Перед
  выдачей username перечитывается через `getChat` (пользователь мог его сменить). Нет username → статус
  `needs_username`, ЛС с кнопкой «Получить приз», окно `CLAIM_WINDOW_DAYS`.
- **2026-11-24 — Деньги:** счёт в USD по прайсу Telegram → TON по курсу (+`RATE_BUFFER`), округление вверх
  до 0.001 TON. Платёж опознаётся по комментарию `SL-XXXXXXXX` (toncenter v3). Недоплата копится (`underpaid`),
  доплата по той же ссылке. Оплата позже `expires_at + 2ч` → не активируется автоматически, админ: `/markpaid <gid>`.
- **2026-11-24 — Казначейство:** `TREASURY_MODE=usdt` — сразу после оплаты TON→USDT (STON.fi), перед
  оплатой Fragment — USDT→TON ровно на нужную сумму +3%. По умолчанию `TREASURY_DRY_RUN=true`.

## 2. Грабли (не наступать повторно)

- **2026-11-24 — initData:** в data-check-string входят **все** поля, кроме `hash`. Поле `signature`
  (новое, для Ed25519-проверки третьими сторонами) **входит**. Не выкидывать его. → `server/src/tg/initData.ts`
- **2026-11-24 — Float в деньгах:** `100 * 0.0199 * 100 = 199.00000000000003`, `Math.ceil` даёт 200.
  Всегда через `ceilCents()` (округление до 1e-6 перед ceil); nano считать в `bigint`. → `pricing.ts`
- **2026-11-24 — `INSERT OR IGNORE` глотает ВСЕ конфликты**, включая `UNIQUE(giveaway_id, ref_code)` —
  коллизия реф-кода выглядела как «уже участвует». Используем `ON CONFLICT(giveaway_id, user_id) DO NOTHING`. → `repo.ts`
- **2026-11-24 — TON seqno:** два перевода с одним seqno — второй молча теряется. Все исходящие переводы —
  через очередь `ServiceWallet.send` (строго по одному, ждём рост seqno). Выдача призов — последовательно.
- **2026-11-24 — Статус `processing` после падения процесса НЕ ретраится автоматически**: перевод мог уже
  уйти → двойная выдача. Сначала проверить кошелёк в tonviewer, потом `/retry <gid> <uid> force`.
- **2026-11-24 — Энтропия розыгрыша фиксируется в БД один раз до вычислений**, иначе повтор после сбоя дал бы
  другой результат (и выглядел бы как «перекрутка»).
- **2026-11-24 — `Repo.updateGiveaway/updateWinner/updateInvoice` строят SQL из ключей объекта.** Никогда
  не передавать туда объект из пользовательского ввода — только литералы из кода.
- **2026-11-24 — Капча проверяется ПОСЛЕ дешёвых условий** (username, страна, подписка): иначе пользователь
  тратит капчу и решает её заново. Капча одноразовая при любом исходе проверки.
- **2026-11-24 — `npm audit` ругается на zod <4.6.6 внутри `@ton/ton`** (транзитивная zod@3). Наш код на zod@4.
  Риск низкий (zod там парсит ответы API). Не делать `npm audit fix --force` — он откатывает `@ston-fi/sdk` до 0.5.
- **2026-11-24 — `@fastify/static` + SPA:** не-API 404 отдают `index.html`, а `/api/*` — JSON 404. Порядок
  регистрации важен (сначала маршруты API).

### Тесты / окружение разработки
- **2026-11-24 — `openSingleWalletModal` помечен в @tonconnect/ui 2.4 как experimental.** При обновлении
  библиотеки проверить, что метод на месте. Список кошельков грузится с config.ton.org; без сети SDK берёт
  встроенный `FALLBACK_WALLETS_LIST`, где `telegram-wallet` есть.
- **2026-11-24 — Playwright `page.evaluate(функция)` под tsx падает с `__name is not defined`** (esbuild
  добавляет хелпер в именованные функции). Передавать код строкой.
- **2026-11-24 — `test/helpers.ts` не импортирует `vitest`** — он используется и в e2e-скриптах вне vitest
  (иначе «Vitest failed to access its internal state»).
- **2026-11-24 — В e2e часы должны идти:** замороженный `ctx.now` даёт время решения капчи 0 мс → `too_fast`.
- **2026-11-24 — В песочнице разработки нет доступа к Telegram/TON/Fragment** (только npm). Внешние вызовы
  покрыты моками; `telegram.org/js/telegram-web-app.js` в Playwright надо `route(...).abort()`. Мини-апп
  работает вне Telegram через заглушку (`DEV_MODE=true` + `/api/dev/initdata`).
- **2026-11-24 — tsx + top-level await:** скрипты-одноразовки называть `.mts`, иначе «Top-level await is not
  supported with the cjs output format». Глобальный Playwright импортировать по абсолютному пути `.../playwright/index.mjs`.
- **2026-11-24 — (для ИИ-ассистента)** heredoc в shell с JS-кодом, где есть `.remove()`, ловится проверкой
  безопасности как «удаление». Файлы создавать инструментом Write, а не `cat <<EOF`.

## 3. Непроверенные допущения (проверить на реальных сервисах!)

Код написан и покрыт тестами на моках, но **с живыми сервисами не запускался** (в среде разработки не было сети).

1. **Fragment** (`fulfillment/fragment.ts`): методы `searchStarsRecipient / initBuyStarsRequest / getBuyStarsLink`
   и `searchPremiumGiftRecipient / initGiftPremiumRequest / getGiftPremiumLink`, параметры `account`/`device`
   (TON Connect), извлечение `hash` со страницы. Официального API нет — формат может меняться. Первый запуск —
   `FULFILLMENT_DRY_RUN=true` на 1 приз 50⭐ и сверить логи; затем боевой режим на себе.
   Возможно, Fragment потребует KYC для покупки в пользу других — проверить в аккаунте.
2. **Ответ `requestContact`** (`response`) подписан тем же алгоритмом, что initData. Если нет — работает
   запасной путь: контакт приходит боту сообщением (`message:contact`), фронт опрашивает статус.
3. **toncenter v3**: поля `in_msg.message_content.decoded.comment`, `in_msg.value`, `description.aborted`,
   `/api/v3/masterchainInfo → last.root_hash`, `/api/v3/jetton/wallets`. Нужен `TONCENTER_API_KEY` (без него 1 rps).
4. **STON.fi**: адрес «нативного TON» для API = `EQAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAM9c`
   (`STONFI_TON_ADDRESS`), `simulateSwap/simulateReverseSwap` + `dexFactory(router)`. Проверить на малой сумме.
5. **Цены по умолчанию** (`TG_STAR_PRICE_USD=0.0199`, Premium 13.99/18.99/34.99, Fragment 0.015 и 11.99/15.99/28.99)
   — ориентировочные. Сверить с актуальными ценами Telegram и Fragment перед запуском.
